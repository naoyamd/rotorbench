# 統合ロボットアーム＋グリッパー設計ベンチマーク計画

**計画版:** 1.0  
**計画確定日:** 2026-07-29  
**状態:** 独立レビュー反映済み・実装開始ゲート未承認・課題パケット未作成・未凍結  
**想定評価期間:** 初回公式実行から12か月  
**仮称:** Integrated Robotic Handling System Design Benchmark

## 0. この計画の位置づけ

この文書は、LLMの製造業における統合設計能力を、今後1年間にわたり同じ尺度で追跡するための旗艦ベンチマークについて、実装開始直前までの設計を確定するものです。

現時点のモデルが完走できるかどうかを課題範囲の制約にはしません。モデルの進歩に伴って、要求解釈、機構構想、CAD、解析、製造設計、検証、設計変更のどこまで到達できるようになったかを継続して測れる難度を優先します。

この計画では、次の作業はまだ行いません。

- 実際の設計課題を候補モデルへ実行させること
- 課題用CAD、ワーク、セル、購入品カタログを作成すること
- 数値要求を推測で決めること
- 基準解、評価器、採点結果を作成すること
- `task-packets/`、`benchmarks/`、`launches/`へ実課題を登録すること
- Stage 1を開始すること

計画書は凍結領域外の`planning/`に置き、既存のStage 0/1/2契約には影響させません。

現行Stage 0 v3は、単一instructionsと平坦なinputs/outputsを中心とするため、本計画のインスタンスbank、可視性クラス、段階checkpoint、後出し変更、採点版、sanitize境界を型として拘束できません。現行Stage 1/2も、複数checkpoint、部分到達、変更イベント、評価レコード、embargoを型として扱いません。実課題を作る前に、旧v2/v3を後方互換で維持したStage 0/1/2 v4相当の型付き契約を実装することを前提とします。

## 1. ベンチマークの目的

### 1.1 主目的

与えられた製造セル要求から、実際に製造・組立・検証へ渡せるロボットマニピュレータを設計する能力を測ります。

単なる3D形状生成ではなく、以下を一つの設計として整合させる能力が対象です。

- 要求分解と優先順位付け
- システム構成と運動学
- アーム、関節、駆動、伝達、支持構造
- 開閉機構を含むグリッパー
- 荷重、剛性、寿命、精度、公差
- 材料、加工、組立、検査、保全
- 安全コンセプト、故障モード、残留リスク
- 設計根拠、検証、トレーサビリティ
- 後出し変更に対する影響分析と再設計

### 1.2 評価しないもの

次の能力を設計品質の主要得点へ混入させません。

- Webサイトや専用ビューワーの制作能力
- レンダリングの美しさ
- CAD部品数、文書量、コード行数
- 特定CAD製品の操作習熟度そのもの
- ベンダー検索やWeb検索の速さ
- モデルの自己申告だけに基づく性能
- 安全認証や法規適合の取得
- 壁時計時間、トークン数、ツール呼出数

時間、費用、トークン、再試行回数は、設計品質とは別の効率指標として記録します。

### 1.3 成功状態

1年後に、単一順位だけでなく、各モデルについて次が説明できることを成功とします。

- 成立設計まで到達できたか
- どの工学領域が強く、どこで破綻したか
- 公開課題だけでなく未見条件へ一般化できたか
- 同一モデルの再実行ばらつきはどの程度か
- 新モデルの改善が測定誤差を超えたか
- 高品質へ到達するために必要な時間・計算資源はどの程度か

## 2. 具体的な設計課題

### 2.1 課題の骨子

**機械加工・検査セル向け、多品種ピック＆プレース用固定台座式ロボットアームと開閉式グリッパーの統合機械設計**

候補モデルは、共通ベースへの取付面から指先までを設計します。複数のワークを供給治具から把持し、セル内の障害物を避け、指定された加工・検査・配置治具へ搬送し、所定の姿勢と精度で解放できるシステムとします。

課題は「特定形式の6軸ロボットを描くこと」ではありません。要求されたタスク空間と製造条件を満たす限り、候補モデルはアームの構成を選択できます。

### 2.2 運用シナリオ

公式課題では、校正を経て次の性質を持つシナリオを固定します。

- 防護された共通試験セル内で運用する
- 異なる形状、質量、重心、表面性状を持つ複数の非危険物ワークを扱う
- 供給、接近、把持、持上げ、移載、位置決め、解放、退避、復帰を繰り返す
- ワークごとに把持可能面、把持禁止面、外観保護面を持つ
- 障害物、治具、狭い接近方向、複数の目標姿勢を含む
- 品種切替と保全姿勢を含む
- 公表されたばらつき範囲に対して成立する
- 初回設計提出後に、同一の変更通知を全候補へ開示する

ワークファミリーは、少なくとも次の異なる設計課題を生む構成にします。

1. 剛体として扱える機械加工部品
2. 接触圧または外観保護に制約のある薄肉部品
3. 偏心した重心または把持方向制約を持つ部品

具体的なワーク形状と数は、複数の設計方式が成立し、かつ自明解にならないことを基準設計と物理試験で確認してから固定します。

### 2.3 設計境界

設計対象は次のとおりです。

- ベース、据付、基準座標系
- アームの自由度構成、関節配置、リンク寸法
- リンク、関節ハウジング、軸、支持構造、機械ストッパー
- モーター、減速機、軸受、ブレーキ、締結部品の選定と組込み
- 駆動・伝達機構と荷重経路
- 手首とエンドエフェクタ接続部
- グリッパーの開閉アクチュエータ
- グリッパーの伝達機構、ガイド、ジョー、指、接触部
- 必要な交換爪、受動コンプライアンス、保持機構
- センサ取付、ケーブル・配管経路、曲げ・保護空間
- カバー、保全アクセス、交換部品
- 製造、組立、調整、校正、検査に必要な設計

### 2.4 購入品として支給する範囲

次の内部設計は行わせず、形状・性能・質量・価格・寿命条件を含む凍結カタログから選定させます。

- モーター
- 減速機
- 軸受
- ブレーキ
- リニアガイド、送りねじ等の標準運動部品
- センサ
- 標準締結部品
- ケーブル、コネクタ、配管
- 必要に応じた標準ツールチェンジャ

候補モデルは、購入品を検索する能力ではなく、要求に対して選定し、配置し、荷重・精度・寿命・保全を統合する能力を示します。

### 2.5 課題外

- モーター、減速機、軸受、センサ自体の内部設計
- 電源回路、サーボドライブ、制御基板
- PLC、安全PLC、上位制御、視覚認識の実装
- 生産用軌道生成ソフトウェアやサーボゲイン調整
- ガード、非常停止回路、セル全体の安全制御実装
- 安全規格・法規への適合認証
- 候補モデルによる実機製作、実機運転、調達交渉

ただし、制御・安全設計へ引き渡すための関節軸、可動域、減速比、慣性、トルク、速度、制動条件、センサ配置、危険源、残留リスクは成果物に含めます。

## 3. 固定条件と設計自由度

| 区分 | 公式課題で固定するもの | 候補モデルが判断するもの |
|---|---|---|
| セル | ベース取付面、治具、障害物、禁止空間、座標系 | アーム構成、設置姿勢、リンク配置 |
| タスク | ワーク、供給・目標姿勢、シーケンス、品質条件 | 運動学構成、代表経路、姿勢余裕 |
| 資源 | 電源、空圧、固定購入品カタログ | 駆動方式、部品選定、減速・伝達方式 |
| グリッパー | 一つの統合グリッパー本体、自動ツール交換なし、把持面、禁止面、ワークばらつき | 開閉方式、ジョー、ガイド、爪、補償機構 |
| 製造 | 許可材料、加工法、検査能力、原価表 | 部品分割、材料、加工、表面処理、基準 |
| 成果形式 | STEP、JSON、BOM、図面、計算、証跡契約 | ネイティブCAD、設計手順、解析手法 |
| 評価 | 荷重ケース、検査器、ゲート、ルーブリック | 設計解、仮定、トレードオフ |

機構形式や軸数の一意解は設けません。共通評価器が可変トポロジーを扱えるよう、リンク・関節・フレーム・状態を中立マニフェストで表します。

初回シーズンでは、同一の開閉機構、駆動源、グリッパー本体を全ワークに使用します。品種切替時の手動爪交換は許可できますが、許可の有無、交換可能なタイミング、切替時間の扱いは校正前に固定します。自動ツールチェンジャで別グリッパーへ交換する方式は初回シーズンの課題外です。

任意トポロジーを標榜しながら評価器が理解できる方式だけを有利にしないため、WP3で次の許容トポロジー文法と評価対応表を事前登録します。

- `supported`: 自動評価と共通再解析に完全対応
- `declarable-manual`: 契約上表現でき、事前登録した盲検手動評価へフォールバック
- `prohibited`: 課題境界または安全な評価能力の外にあるため使用不可

直列、閉ループ、差動、並列、ケーブル伝達、弾性要素などを個別に分類します。`declarable-manual`に含めた方式を、評価器未対応だけを理由に設計失敗へしません。評価結果は`design failed`、`artifact invalid`、`evaluator unsupported`、`evaluator uncertain`を区別します。

## 4. 入力パケット計画

### 4.1 公開入力

候補モデルへ渡すパケットには、少なくとも次を含めます。

- 課題説明と要求一覧
- セル、ベース、治具、障害物のSTEP
- ワークファミリーのSTEP、PMIまたは等価製造情報
- ワークの質量、重心、慣性、寸法・物性ばらつき
- 把持可能面、把持禁止面、許容接触条件
- 供給姿勢、目標姿勢、退避姿勢、保全姿勢
- 運転シーケンスと荷重ケース
- 許可材料、加工法、表面処理、組立・検査能力
- 購入品の凍結形状・性能カタログ
- 原価・調達リードタイムの固定スナップショット
- 共通安全セルとの機械・電気・信号インターフェース
- 単位、座標、命名、部品識別規則
- 提出スキーマと公開サニティ検査
- 凍結したCAD・STEP・解析実行環境

すべての入力は、出所、ライセンス、測定方法、不確かさ、ハッシュを持たせます。評価に使う情報を外部Web検索に依存させません。

### 4.2 可視性クラス

「候補に見せない入力」を一括りにしません。各アセットに`visibilityClass`、`disclosedAt`、`requirementRefs`、`digest`を持たせ、次へ分離します。

1. **`candidate-public`**  
   共通要求、成果契約、公開サニティ検査。すべての候補が開始時に参照します。

2. **`run-private-instance`**  
   現在の候補には実行開始時に完全開示する、セル、ワーク、姿勢、カタログ等の具体的な課題インスタンスです。後続候補と一般公開には評価期間終了まで伏せます。候補が設計すべき要求を隠したまま評価することはありません。

3. **`evaluator-hidden-robustness`**  
   公開済みの公差、摩擦、重心、姿勢等の許容範囲から事前生成した具体ケースです。同じ設計のロバスト性だけを検査し、新しい要求を追加しません。

4. **`event-private-change`**  
   基本設計をハッシュ固定した後、その候補へ初めて開示する設計変更です。各実行で同じevent digestを使用し、成果と通知内容は評価期間終了までembargoします。

5. **`evaluator-secret`**  
   抜け道防止用の評価器実装詳細、seed、境界ケースです。設計要求は含めません。

Fresh Variantは、固定アンカーとは別の`run-private-instance`として扱い、候補にはその実行開始時に必要情報を完全開示します。

### 4.3 版、コミットメント、開示

- 可視性クラスごとに別マニフェストを作る
- run-private、robustness、change、evaluator-secretは公式実行前にタイムスタンプ付きdigestまたはseed commitmentを記録する
- 各開示で時刻、対象run、event digest、候補の受領証跡を保存する
- 評価期間中は後続候補が見られないよう、run-private入力、change、完全成果をembargoする
- コホート封印後、課題内容を逆算できないGate・能力ベクトル・不確かさだけは、漏えいレビューを経て途中公開できる
- 公開デモ用成果は随時公開できるが、固定アンカーの入力、完全CAD、計算書、変更成果とは分離する
- 法的に公開不能な一次資料を除き、期間終了時に入力、seed、評価器、採点仕様、結果を原則開示する
- 非開示項目は理由、管理者、digest、監査方法を残す
- 変更は上書きせず新しい課題版として扱う

## 5. 候補モデルの成果物

### 5.1 段階成果

最終アセンブリが未完成でも能力の到達点を識別できるよう、次のチェックポイントを順に固定します。

1. 初期計画、要求分解、仮定、検証方針
2. 代替案比較、システム構成、運動学スケルトン
3. 関節、リンク、駆動、支持構造の詳細
4. 開閉機構を含むグリッパーと把持設計
5. 統合アセンブリと代表状態
6. 計算、図面、BOM、製造・組立・保全計画
7. 検証結果と要求トレーサビリティ
8. 後出し変更の影響分析と改訂版

各チェックポイントは時刻、ハッシュ、親チェックポイントを記録し、後から書き換えません。候補の自己申告だけにせず、オーケストレータがappend-onlyのcheckpoint receiptを発行し、checkpoint tree digestと受領時刻を拘束します。変更イベントは、基本設計receiptの発行成功後にだけ開示します。

チェックポイントは証拠を固定する論理境界であり、モデルの内部作業をウォーターフォール順に強制するものではありません。候補は各境界の間で、構想、CAD、計算、検証を反復できます。基本設計と変更影響分析の固定時点だけは、後出し編集を防ぐため厳密に分けます。

### 5.2 必須提出物

フルアームの全製作図を一律必須にすると、設計判断よりCAD・製図スループットが支配的になります。成果物を次の三層へ分けます。

**全体成立に必須**

- 統合アセンブリSTEP
- 全構成部品を識別できるBOM
- 指定代表姿勢とグリッパー状態のSTEP
- 要求、仮定、設計判断、検証のトレーサビリティ
- 運動学・関節・部品対応マニフェスト
- 代表waypointと状態遷移データ
- システムレベルの荷重、駆動、構造、把持、精度計算
- リスク記録、故障モード、安全コンセプト
- 未検証事項、限界、追加試験計画
- 変更前後の差分、影響分析、再検証結果

**Critical design setに必須**

- 最大負荷関節
- 精度支配関節またはリンク
- 開閉機構を含むグリッパー
- 事前登録した選定規則が指定する追加部位

これらについて、製作部品STEP、製作図またはPMI、材料・加工・表面処理、詳細計算、共通再解析定義、公差スタック、組立・調整・検査・保全手順を必須とします。critical setは運動学スケルトン固定後、事前登録した規則で主催側が決め、候補が都合のよい部位だけを選べないようにします。

**成熟度・生産引渡し指標**

- 全製作部品の詳細図
- 全工程表
- 全部位の検査計画
- 完全な組立・保全資料

これらは`Production release readiness`として別表示し、基本の設計品質点や必須ゲートをファイル生成量で支配しないようにします。

中立STEPと共通マニフェストを採点の正本とします。ネイティブCADは補助提出です。再生成を採点する場合は、主催側が提供する共通authoring APIまたは指定再生成コンテナを正規経路とし、異なるネイティブCADを使う場合は別execution profileとして扱います。

### 5.3 共通運動マニフェスト

STEPだけでは運動関係を十分に表現できないため、JSON Schemaで次を必須化します。

- 単位系、座標系、手系、基準姿勢
- リンク・関節グラフとSTEP内の部品ID
- 関節種別、軸、原点、可動域
- 宣言速度、加速度、トルク、減速比
- 駆動系、伝達系、ブレーキ、センサの対応
- グリッパー開閉状態、ジョー、把持点、接触面
- ワーク、治具、障害物、禁止空間の参照
- 供給、把持、移載、配置、退避、保全の代表状態
- 軌道サンプルと時間情報
- BOM、図面、計算、試験、要求への証跡リンク

マニフェスト値は、入力パケットの要求IDまたは候補の仮定IDを参照させます。

### 5.4 候補ソースの信頼境界

候補が提出したCAD生成ソース、マクロ、スクリプト、ネイティブCADを、封印評価器と同じ環境では実行しません。

- 一時的なsandboxを候補runごとに作る
- ネットワーク、資格情報、他run、封印アセットへのアクセスを禁止する
- 入力パケットを読取専用でマウントする
- CPU、メモリ、ストレージ、実行時間、プロセスを制限する
- 外部リンク、埋込スクリプト、未許可マクロを拒否する
- 許可されたSTEP、JSON、CSV、PDF、画像だけを出力できるようにする
- 出力を別工程でsanitizeし、メタデータと能動コンテンツを除去する
- 封印評価環境へ渡すのはsanitize済み中立成果だけとする
- sandbox、egress、provenance、sanitizationの全ログをdigest-boundにする

## 6. 求める工学検討

計算手法に一意解は設けません。共通評価器は、候補の自己申告値を採用せず、入力、STEP、マニフェストから可能な範囲を独立再計算します。

### 6.1 システム・運動学

- 自由度構成と要求姿勢の対応
- 順運動学、逆運動学、作業空間
- 関節限界、機械ストッパー、特異姿勢
- 姿勢余裕、可操作度、軌道成立性
- 可動部、治具、障害物、ワーク、ケーブルの干渉
- 掃引体積と禁止空間

候補には代表waypointと成立根拠を提出させますが、サイクル・荷重評価の正本には、主催側の決定的な共通軌道生成器と共通運動則を使用します。共通前提には、速度、加速度、jerk、encoder分解能、制御帯域、補償モデル、停止則を含めます。軌道計画ソフトウェアや制御器の実装能力を、機械設計能力へ混入させないためです。

精度は、候補設計だけで決まる`mechanical error budget`と、共通制御前提を加えた`system performance estimate`を別表示します。物理校正でも主催側の共通制御器を使用し、その性能差を候補得点へ入れません。

### 6.2 駆動・構造

- 質量、重心、慣性
- 静荷重、動荷重、偏心、停止・保持荷重
- 関節トルク、速度、加速度、制動
- モーター、減速機、ブレーキの容量とデューティ
- 軸、軸受、締結、伝達部の強度と寿命
- リンク、関節、接合部の剛性、たわみ
- 必要に応じた振動、固有振動、熱
- ケーブル・配管の曲げ、引張、干渉、寿命

### 6.3 グリッパー・ワーク

- 開閉ストローク、ガイド、停止端、バックラッシュ
- 駆動源から指先までの力伝達
- 把持力、摩擦変動、滑り、脱落
- 加速度、姿勢、非常停止相当条件での保持
- 接触圧、ワーク変形、外観保護
- ワーク公差、位置ずれ、重心偏差
- 電源・圧力喪失時の挙動
- 指、ジョー、ガイド、締結部の強度と交換性

### 6.4 精度・公差

- ベースからTCPまでの誤差予算
- 部品・組立公差の累積
- バックラッシュ、弾性変形、熱、校正残差
- 基準、位置決め、調整、交換後の再現性
- 代表姿勢とワークばらつきに対する確率的評価

### 6.5 製造・組立・保全

- 材料、製法、後加工、表面処理
- 基準面、重要寸法、検査方法
- 工具アクセス、加工可能性、組立順序
- 位置決め、締結、調整、校正
- 摩耗部品、潤滑、交換、故障切分け
- 保全姿勢、アクセス空間、再校正
- 部品標準化、質量、原価、組立工数

### 6.6 リスク・安全

- 可動部、挟圧、衝突、落下、残留エネルギー
- 予見可能な誤使用と保全作業
- 電源・圧力・通信喪失時の機械的状態
- 機械的保持、ブレーキ、ストッパー、カバー
- 検出すべき故障と上位安全システムへの要求
- 残留リスクと実機試験前の安全承認条件

ここで求めるのは安全コンセプトと設計上のリスク低減であり、認証適合の宣言ではありません。

安全ゲートは文書の有無だけで通しません。少なくとも、保持ブレーキ容量、電源・圧力喪失時の落下防止、機械ストッパー、保全支持、残留エネルギー解放、挟圧部の機械的低減または上位ガードinterfaceを、共通荷重ケースと形状から客観評価します。

## 7. 評価・採点計画

### 7.1 表示する評価結果

各候補について、次を同時に表示します。

1. Admissionの有効性
2. 段階到達プロファイル
3. Baseline qualification
4. Change qualification
5. 10次元の能力ベクトル
6. 成立した基本設計だけに表示する100点換算
7. Raw metrics
8. 専門家評価の不確かさ
9. 再実行ばらつき
10. 品質とは分離した効率指標

総合順位だけを表示して、重大な設計不成立や能力差を隠すことはしません。

採点仕様の完全版は公式実行前にハッシュ固定し、独立監査者が閲覧できる状態にします。候補モデルへは、要求、完了条件、ゲートカテゴリ、必要な証拠を提示しますが、封印ケース、境界値、正解誘導につながる内部テストは提示しません。12か月の評価期間終了後、監査可能な採点仕様と封印情報を開示します。これは、既存Stage 1契約の「候補は採点・比較へアクセスしない」という境界と両立させます。

結果は最初から次の独立パネルに分けます。

- `Public demonstration`: 公開デモ課題の結果。縦断主得点には使わない
- `Fixed-anchor private baseline`: シーズン開始前に固定したアンカー群。1年間の縦断主得点
- `Hidden robustness`: 公開済み許容範囲内の摂動に対するロバスト性
- `Change response`: 基本設計固定後の変更対応
- `Fresh generalization`: 新規run-private Variantへの一般化。補助指標

Fresh Variantを年途中で既存の主得点へ加えません。複数パネルを将来合成する場合は、合成式、欠測処理、等化誤差を最初の公式実行前に固定し、過去結果も同じ版で再評価できる場合に限ります。

採点パネルは、このベンチマーク専用のv4 evaluation recordと結果ページに置きます。共通の`/compare`は、異なるベンチマークや旧成果を混ぜず、従来どおり中立・無順位の一覧として維持します。

### 7.2 必須ゲート

| Gate | 名称 | 判定内容 |
|---|---|---|
| A0 | Admission | task/launch identity、初期計画checkpoint、最低限のmanifest、安全なパス、提出済みファイルのhashが検証可能 |
| B0 | Baseline completeness | 基本設計で要求された全体成立成果とcritical design setが評価可能 |
| B1 | 幾何・運動成立 | 取付、必須姿勢、経路、関節範囲、開閉、禁止空間、干渉が成立 |
| B2 | 把持・ワーク保護 | 全指定ワークを保持し、接触・変形・禁止面条件を満たす |
| B3 | 機械的成立 | 駆動、構造、軸受、締結、伝達、制動が全荷重ケースで成立 |
| B4 | 精度・公差成立 | 指定精度とばらつきに対し、誤差予算と調整・校正が閉じる |
| B5 | 製造・組立成立 | 許可工程で製造でき、組立、調整、検査、主要保全に重大矛盾がない |
| B6 | 機械的安全最低条件 | 保持、落下防止、停止、ストッパー、保全支持、残留エネルギー、挟圧低減が課題境界内で成立 |

- A0不通過だけを`Invalid submission`とします。別課題、改ざん、不正形式、危険な能動コンテンツ等に限定します。
- 必須成果物の欠落、CAD不成立、計算不足は`missing`または`not evaluable`とし、B0〜B6と対応能力次元へ反映します。
- B0〜B6を通過した基本設計を`Baseline qualified`とします。
- 変更後成果へB0〜B6を再適用し、通過したものを`Change qualified`とします。
- 変更失敗は、成立済み基本設計の資格と基本設計得点を取り消しません。
- 不通過でも、診断目的の段階到達、能力ベクトル、Raw metricsは表示します。
- Baselineの100点換算は`Baseline qualified`だけに表示し、Changeは別得点として表示します。
- 一つの高得点領域で重大な不成立を相殺させません。

閾値は本計画段階では置かず、物理校正、基準設計、測定不確かさを根拠にStage 0で事前登録します。

### 7.3 10次元の能力ベクトル

| # | 評価次元 | 主な評価方法 | 公式配点 |
|---:|---|---|---|
| 1 | 要求分解・システム構想 | 証拠被覆＋盲検専門評価 | WP6/WP8で校正 |
| 2 | 運動学・作業空間・サイクル成立 | 共通再解析中心 | WP6/WP8で校正 |
| 3 | グリッパー・把持堅牢性・ワーク保護 | 共通再解析＋物理校正＋盲検評価 | WP6/WP8で校正 |
| 4 | 荷重経路・構造・駆動・寿命 | 共通再解析＋盲検評価 | WP6/WP8で校正 |
| 5 | 精度・公差・調整・校正 | 誤差再計算＋盲検評価 | WP6/WP8で校正 |
| 6 | DFM・DFA・検査・保全 | ルール検査＋盲検評価 | WP6/WP8で校正 |
| 7 | 安全・信頼性・故障時挙動 | 機械ゲート＋盲検評価 | WP6/WP8で校正 |
| 8 | 検証品質・根拠・トレーサビリティ | 証拠整合＋盲検評価 | WP6/WP8で校正 |
| 9 | 後出し変更への設計対応 | 差分再解析＋盲検評価 | WP6/WP8で校正 |
| 10 | 質量・原価・エネルギーのPareto品質 | 固定モデルによる定量評価 | WP6/WP8で校正 |

この10次元は本計画で固定します。100点への配点、自動評価と専門評価の比率は、工学値と同様に推測で置きません。人間基準設計、held-out architecture、意図的欠陥設計、パイロット出力に対するFMEA型影響分析、重複分析、感度分析、物理予測妥当性からWP6/WP8で決め、証拠IDとユーザー承認を付けます。最初の公式実行後は12か月固定し、得点結果を見て変更しません。

### 7.4 段階到達プロファイル

未完走候補について、`未提出`、`試したが失敗`、`評価器が扱えない`を混同しません。各段階と各能力次元へ次を記録します。

- `attempted`
- `evidenceCoverage`
- `evaluable`
- `passFail`
- `scoreInterval`
- `failureCause`
- `highestVerifiedCheckpoint`

これを`Engineering Attainment Profile`として表示し、成立設計の100点換算とは明確に分けます。

### 7.5 専門家ルーブリック

各専門評価項目は、証拠アンカー付きの0〜4で評価します。

- **0:** 証拠なし、重大な矛盾、要求と反対
- **1:** 主張のみ、成立に必要な根拠が不足
- **2:** 公称条件では概ね整合
- **3:** 指定ばらつき、製造、組立、検証まで一貫
- **4:** 変更・故障・検証を見越し、根拠、余裕、限界が明確

採点者は、文章の巧拙ではなく、要求、計算、CAD、図面、BOM、検証の相互参照を証拠として採点します。

- 主催側が標準render、標準BOM、標準証拠票へ変換する
- ファイル名、著者、CAD metadata、履歴、自由文識別子を除去する
- モデル名、プロバイダー、推論設定を隠す
- 独立採点者数と集約方法を一致度パイロットで決める
- 事前登録した幅を超える不一致は、根拠を残して第三者裁定する
- 次元別一致度、評定者間相関、信頼区間を記録する
- 一致度の受入値は、年次差を誤反転させない条件からパイロットで決める

### 7.6 Raw metrics

少なくとも次の生データを、総合点とは別に保存します。

- 要求トレーサビリティ被覆率、未解決要求数
- 必須姿勢・兄弟ケースの到達率
- 衝突件数、最小クリアランス、禁止空間侵入
- 関節余裕、特異性指標、軌道時間
- ピーク・連続トルク、速度、熱、制動余裕
- 応力、変位、剛性、固有振動、寿命余裕
- 把持力、滑り余裕、接触圧、ワーク変形
- TCP誤差予算、公差モンテカルロ成立率
- 質量、重心、基礎モーメント、消費エネルギー
- CAD・BOM・図面・計算の参照整合率
- 加工工程、セットアップ、固有部品、固有締結品、概算原価
- 組立・交換・保全アクセスの成立率
- 変更影響の要求・部品・計算・検証被覆率
- 候補計算と独立再計算の差

原価には、モデル版、数量、地域、通貨、基準日、不確かさを付けます。エネルギーには、機械出力、駆動損失、補機をどこまで含むかという評価境界と不確かさを付け、単一の見かけ精度の高い値にしません。

### 7.7 効率指標

次はEQIへ加点・減点せず、別軸で表示します。

- 経過時間、実行時間
- 入出力トークン
- ツール呼出数
- 失敗・再実行・再生成回数
- 外部支援または人手介入
- 計算資源と推定費用
- 必須ゲート通過までの反復数

品質と効率は単一の点へ混ぜません。公式設計品質画面とは別のページまたはタブに置き、品質順位へ使用しないことを明記します。

## 8. 後出し変更イベント

### 8.1 手順

1. 候補が基本設計、計算、検証を提出する
2. 基本設計をハッシュ固定する
3. そのrunに対し、固定済みの同一event digestを個別に開示する
4. 影響分析を先に固定する
5. 改訂設計と差分検証を提出する
6. 変更後ゲートと変更対応得点を評価する

モデルは異なる時期に実行されるため、暦上の同時開示は行いません。各runで同じ論理時点に開示し、開示時刻、event digest、受領証跡を保存します。変更通知と変更後成果は評価期間終了までembargoし、後続モデルが事前に知ることを防ぎます。

### 8.2 変更イベント族

- ワークの質量、重心、形状、公差、把持禁止面の変更
- 供給・目標姿勢または障害物の変更
- モーター、減速機等の購入品の使用禁止・代替
- サイクル、デューティ、停止荷重の変更
- 設置包絡または保全アクセス条件の変更

変更数、組合せ、難度は校正試験で決めます。変更は解決可能であり、元課題を不当に無効化しないことを人間基準設計で確認します。

### 8.3 評価対象

- 影響範囲の特定
- 変更不要箇所を維持する判断
- 局所修正と全面再設計の選択根拠
- 要求、計算、CAD、図面、BOM、検証の更新
- 変更後の成立性
- 新たな不整合や退行の有無
- 初期構想に持たせた余裕の妥当性

変更部品数の少なさ自体は加点しません。

基本設計と変更設計の資格・得点は別表示します。変更後の不成立が、すでに成立した基本設計の資格を遡って取り消すことはありません。

## 9. 1年間の比較性

### 9.1 三層構造

1. **公開フレームワーク**  
   成果形式、能力ベクトル、ゲート、評価方法、実行条件を12か月固定します。

2. **アンカー・インスタンス群**  
   最初の公式実行前に複数の非公開兄弟ケースを固定し、同じ割当規則で繰り返し使用します。これだけを1年間の縦断主得点に使います。

3. **Fresh Variant群**  
   公開成果の模倣や課題汚染を検出するため、同じ能力構造を持つ新規run-privateケースを投入します。Fresh結果は一般化の補助指標として別表示し、年途中に既存の縦断主得点へ混ぜません。

### 9.2 絶対尺度

- 百分位、偏差値、同時期の候補内順位を総合点に使わない
- ゲート、100点尺度、Raw metricsを事前登録する
- 人間基準設計と欠陥対照を回帰試験へ使う
- 新Variantはアンカーとの専門家・物理校正で等化するが、等化誤差も別表示する
- 評価器を修正した場合は新しい評価版とし、アンカーモデルを再実行する
- 旧結果を新評価版へ黙って換算しない
- 年途中生成したVariantを、過去の縦断主得点へ直接加えない

### 9.3 再実行と不確かさ

- 同一モデル・同一設定を複数回実行し、モデル内分散を測る
- 公式反復数はパイロットの分散と検出力分析から固定する
- 代表値だけでなく区間を表示する
- 前回との差が、実行分散、採点者分散、課題等化誤差を超えるかを示す

### 9.4 実行条件

- 課題パケット、実行環境、CADカーネル、評価器をハッシュ固定する
- クリーンな隔離環境から開始する
- 現在runへ開示すべきrun-private instance以外の封印情報、他候補成果、採点を候補へ見せない
- ツール、権限、ネットワーク、CPU、メモリ、時間、トークン予算を統一する
- モデル、プロバイダー、推論設定、実行日時、取得可能なmodel revision、API response metadata、system fingerprintを運用側が記録する
- provider側のsilent updateを識別できない場合は、その制約を結果へ明示する
- 環境差が残る場合は別execution profileとして扱い、同一比較群へ混ぜない

新モデルが旧execution profileで動かずprofile変更が必要な場合は、利用可能なアンカーモデルを旧・新profileの両方で`bridge run`します。profile effectとモデル差を分離して表示し、bridge不能なら横断比較を中止して同一profile内比較に限定します。

## 10. 物理的な裏付けと評価器校正

### 10.1 基準設計

人間の機械設計チームが、候補モデルと同じ入力・提出契約で、少なくとも2つの異なる成立アーキテクチャを設計します。

- 唯一の模範解としては使わない
- 複数の設計方式が成立することを確認する
- 評価器と提出契約の正常系回帰試験に使う
- 得点の床・天井と感度を確認する

少なくとも1つの統合基準設計を物理試作し、代替アーキテクチャは必要に応じて重要関節・グリッパー・リンクの試験体を製作します。

評価器を基準設計の方式へ過適合させないため、評価器開発チームとは別の設計チームが`held-out architecture`と`challenge design`を作成します。これらは評価器完成まで隠し、対応方式、manual fallback、unsupported判定が意図どおり働くかを確認します。

### 10.2 意図的欠陥対照

基準設計から、一つの原因と一つの期待失敗を持つ欠陥版を作ります。

- 最悪姿勢でのトルク不足
- 構造剛性または寿命不足
- 掃引中の干渉
- 把持・滑り・接触条件の不足
- 単位、座標、関節対応の誤り
- 公差基準の不整合
- 組立・工具アクセス不能
- 保全部品の交換不能
- ケーブル・配管の曲げ・干渉不足
- 故障時保持・保全状態の欠落

各欠陥を評価器が意図した理由で検出できることを確認します。

### 10.3 物理校正

1. セル、治具、計測器、座標系を校正する
2. ワーク寸法、質量、重心、慣性、表面・摩擦を測定する
3. 基準設計を試作し、主催側の共通制御器で作業域、軌道、把持、たわみ、精度、保全を測る
4. 重要な欠陥対照を安全な試験体で確認する
5. 提出計算、共通再解析、専門評価、実測の差を比較する
6. 差を入力不足、モデル化誤差、製造ばらつき、設計誤りへ分類する
7. 計算許容差、ゲート、Raw metrics、ルーブリック境界を事前登録する
8. 校正記録、測定不確かさ、期待結果をハッシュ固定する

候補設計の選択的な試作結果を主スコアへ加えると公平性が崩れます。物理試作は主に評価器の校正・監査に使用します。物理製作を公式得点へ含める場合は、同一コホートの全候補を同じ加工・組立・試験条件で製作する別トラックとして実施します。

校正結果は、許容トポロジーと解析クラスごとの`calibration coverage matrix`にします。物理検証または妥当な等価性証明がないクラスは、自動得点の対象にせず、`declarable-manual`または`evaluator-uncertain`へ落とします。

## 11. 数値仕様の確定計画

本計画では工学値を推測しません。Stage 0実装時に、次の方法で値を確定します。

| 決定対象 | 確定方法 |
|---|---|
| ワーク形状、質量、重心、慣性 | 実サンプルの測定、図面・STEP照合、測定不確かさ評価 |
| 寸法・摩擦・接触ばらつき | ロット測定、接触試験、必要に応じた材料試験 |
| セル寸法、姿勢、禁止空間 | 実セル要件と測量、複数参照アーキテクチャの運動学掃引 |
| 必要精度・繰返し性 | 下流工程の品質要求、計測能力、基準機の実測から誤差予算化 |
| 可搬、加速度、停止、サイクル | 工程要求と荷重スペクトル、駆動・熱デューティの実現可能性フロンティア |
| 把持力、接触圧、変形 | ワーク試験、接触解析、滑り・落下試験 |
| 応力、変位、振動、寿命 | 複数基準設計の解析収束試験、材料・接合試験、物理計測 |
| 購入品性能 | メーカー一次資料と必要な受入試験を凍結カード化 |
| 製造・検査制約 | 実加工設備、工具、工程能力、検査能力の確認 |
| 原価・リードタイム | 同一時点の固定見積・標準原価スナップショット |
| 実行予算・反復数 | 人間および複数世代モデルのパイロット、分散・検出力分析 |
| ゲート閾値 | 基準設計、欠陥対照、実測、評価器誤差から導出 |
| 得点重み | FMEA型影響分析、重複・感度分析、物理予測妥当性 |
| 査定者一致度の受入値 | 年次差を誤反転させないための信頼性分析 |

すべての工学値は、既存Stage 0の`engineeringValues`に対応する証拠IDを持ち、`resolved`になるまで課題パケットを凍結しません。

## 15. 主要リスクと対策

| リスク | 対策 |
|---|---|
| 課題が巨大で完走可否しか見えない | 段階成果、サブシステム得点、Raw metricsを保存 |
| CAD操作量が設計能力を支配する | 共通環境、中立STEP、共通マニフェスト、設計判断とCAD成立度を分離 |
| もっともらしい自己申告が通る | 主催側の独立再解析と証拠照合 |
| 唯一解へ誘導する | 機能と境界だけを固定し、複数基準アーキテクチャで確認 |
| 公開結果の模倣・学習汚染 | 封印兄弟ケース、Fresh Variant、後出し変更 |
| 封印条件が不公平になる | 公開要求の許容範囲内に限定し、事前ハッシュ、後日監査 |
| 総合点が重大欠陥を隠す | 必須ゲートと能力ベクトルを総合点より先に表示 |
| 専門家採点が不安定 | 盲検3名、証拠アンカー、裁定、一致度と不確かさを表示 |
| 物理とデジタルが乖離する | 基準設計の物理試作、欠陥対照、評価器校正 |
| 年途中の評価器変更で尺度が切れる | 新評価版、アンカー再実行、旧結果を上書きしない |
| 特定ソフト・ベンダーに有利 | 固定カタログ、ソフト非依存成果、同一実行環境 |
| 安全認証を誤って評価する | 安全コンセプトとリスク設計のみを評価し、認証主張を禁止 |

## 18. この計画完了時点の判断

本ベンチマークは、グリッパー単体ではなく、**ベース取付面から指先までのロボットアームと開閉式グリッパーの統合設計**を旗艦課題とします。

現時点のモデルが完走できない場合も、それ自体を失敗とはみなしません。段階成果、必須ゲート、10次元能力ベクトル、Raw metricsにより、各モデルがどこまで到達したかを記録します。

一方で、難しさのために工学的な根拠が曖昧になることは許しません。数値要求は、実ワーク測定、複数の人間基準設計、共通再解析、物理試作、測定不確かさ、独立レビューを経てからのみ固定します。
